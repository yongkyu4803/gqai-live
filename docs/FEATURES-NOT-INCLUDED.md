# 원본에 있었지만 이 저장소에 넣지 않은 기능

이 저장소는 원작자가 개인적으로 쓰는 Mac 앱(GQAI Live)에서
**"말하기 → 라이브 전사 → Claude 정리 → 앞 앱 입력창에 넣기"** 만 떼어 낸 최소판입니다.

원본에는 아래 기능이 더 있었습니다. 코드는 들어 있지 않으니, 필요하면 직접 붙이세요.
각 항목에 **원본이 어떻게 동작했는지**, **어디에 붙이면 되는지**, **주의할 점**을 적었습니다.
AI 코딩 도구에 "이 문서의 ○○ 기능을 넣어 줘"라고 시켜도 되도록 썼습니다.

| # | 기능 | 난이도 |
|---|---|---|
| 1 | 파일 전사 (녹음 파일 올려서 전사) | 중 |
| 2 | 전사 기록 자동 저장과 보관 기간 | 중 |
| 3 | 마크다운 보기·편집 | 중 |
| 4 | 선택 부분 고치기·질문하기·말로 고치기 | 중 |
| 5 | 여러 정리 양식, 전체 다시 쓰기, 녹음 후 전체 다듬기, 문체 예시 | 하 |
| 6 | 시스템 소리 전사 (회의·영상 소리) | 상 |
| 7 | 용어 사전 고급 기능 (CSV, 자동 학습) | 하 |
| 8 | 그 밖의 편의 기능 | 하 |

## 1. 파일 전사

**원본 동작**
- 화면에 "파일 전사 / 라이브 전사" 탭이 있었고, 오디오 파일(WAV, MP3, M4A, AAC, FLAC, OGG, WebM, 최대 200MB·2시간)을 올리면 전체를 전사했습니다.
- 브라우저에서 구간을 골라 미리 듣고 일부만 전사할 수도 있었습니다(Web Audio로 디코딩 → 고른 구간을 WAV로 잘라 보냄).
- 서버는 받은 파일을 **ffmpeg**로 16kHz 모노 WAV로 바꾼 뒤 Whisper로 전사했습니다.
- 긴 파일은 시간이 오래 걸리므로 **작업(job) 방식**이었습니다: `POST /api/transcribe` → `{id}` (HTTP 202), 화면이 `GET /api/jobs/{id}`를 0.5~0.7초마다 물어봐 `running / done / error`를 확인.
- whisper-server가 안 뜨면 `whisper-cli`로 대신 처리했습니다(`-otxt -nt`, 용어 사전은 `--prompt`).

**붙일 곳**
- `server/server.py`: 지금 `/api/transcribe`는 라이브 구간(16kHz WAV, 21초 이하)만 받습니다. 파일용 경로(예: `/api/transcribe/file`)를 따로 만들고, ffmpeg 변환 + 작업 큐를 추가합니다.
- `web/`: 파일 선택 화면과 진행 표시. 결과는 지금의 "원문" 칸에 넣고, 정리는 5번의 "전체 다시 쓰기"로 한 번에 하는 것이 자연스럽습니다.

**주의**
- ffmpeg가 필요합니다(`brew install ffmpeg`). 경로를 하드코딩하지 말고 PATH나 설정값으로 찾으세요.
- 전사 하나가 길게 Whisper를 붙잡으면 라이브 전사가 기다리게 됩니다. 원본은 잠금(lock) 하나로 둘을 직렬화하고, 바쁘면 HTTP 409를 돌려줬습니다.
- 업로드 크기 제한(원본 약 270MB 요청 본문)과 base64 부풀림(약 1.33배)을 고려하세요.

## 2. 전사 기록 자동 저장과 보관 기간

**원본 동작**
- 녹음이나 파일 전사를 하면 기록이 자동 저장됐습니다(편집도 몇 초 뒤 자동 저장).
- 저장 구조:
  ```
  transcripts/<uuid>/
    meta.json        {id, kind: live|file|text, created, updated, language, name, raw_chars, organized_chars}
    raw.txt          원문
    organized.md     정리된 글
    seg-00001.wav …  라이브 구간 음성(16kHz) — 나중에 합쳐 audio.wav로
    audio.wav        파일 전사의 변환된 음성
  ```
- **보관 기간**: 계속 보관 / 1년 / 1개월 / 1주 / 24시간 / 보관 안 함. 서버가 1시간마다(그리고 설정을 바꿀 때) 기간이 지난 기록 폴더를 지웠습니다.
- 헤더의 "전사 기록" 버튼 → 모달에 목록(제목·날짜·글자 수), 열기·삭제·전체 삭제.
- **다시 전사**: 저장된 음성을 지금의 용어 사전으로 다시 전사(사전을 고친 뒤 옛 녹음을 다시 돌릴 때).
- API: `GET /api/transcripts`, `GET /api/transcripts/{id}`, `GET /api/transcripts/{id}/audio`, `POST /api/transcripts/save`, `POST /api/transcripts/delete` (`{id}` 또는 `{all: true}`), `POST /api/transcripts/retry`.

**붙일 곳**
- 새 모듈 `server/library.py`(저장·목록·삭제·보관 기간 정리 스레드)와 위 API.
- `web/app.js`: 녹음 시작 때 기록 id를 만들고, 구간 전사 요청에 `record` id를 넣어 서버가 구간 WAV를 저장하게 합니다. 원문·정리본은 바뀔 때 디바운스해서 저장.

**주의**
- 기록에는 개인 대화가 들어갑니다. 저장 폴더를 `.gitignore`에 넣고, 기본 보관 기간을 짧게 두는 것도 고려하세요.
- id는 UUID 형식만 허용해 경로 조작(`../`)을 막으세요.
- 쓰는 중 앱이 꺼져도 깨지지 않게 임시 파일에 쓴 뒤 `replace`로 바꾸세요.

## 3. 마크다운 보기·편집

**원본 동작**
- 정리된 글을 **보기**(서식 있는 화면)와 **편집**(마크다운 원문) 중 골라 볼 수 있었습니다.
- 외부 라이브러리 없이 작은 마크다운 렌더러를 직접 썼습니다: 제목, 문단(줄바꿈 유지), 중첩 목록, 인용, 표, 코드 블록, 구분선, 굵게·기울임·코드·취소선·링크(http/https만). 입력은 먼저 이스케이프.
- 핵심 아이디어: 렌더링한 블록마다 **원문에서의 위치**(`data-s`, `data-e` 속성)를 붙여, 보기 화면에서 고른 부분을 원문 범위로 되돌릴 수 있게 했습니다(4번 "선택 고치기"에 필요).
  고른 글자가 그 블록 안에 한 번만 나오면 정확한 범위, 아니면 블록 전체를 범위로 썼습니다.

**붙일 곳**
- `web/markdown-view.js` 같은 파일 하나와 "보기/편집" 전환 버튼. 텍스트 영역(`#organized`)을 유일한 원본으로 두고, 보기 화면은 바뀔 때마다 다시 그립니다.
- 지금 최소판은 "입력용" 정리라 마크다운을 쓰지 않습니다. 5번의 다른 양식을 넣을 때 함께 넣으세요.

**주의**
- 직접 렌더러를 쓰면 XSS를 조심해야 합니다(이스케이프 먼저, 링크는 http/https만). 라이브러리(marked + DOMPurify 등)를 써도 됩니다.

## 4. 선택 부분 고치기·질문하기·말로 고치기

**원본 동작**
- 정리된 글에서 일부를 고르고 지시를 쓰면(예: "더 간결하게", "목록으로") 그 부분만 다시 써서 바꿨습니다. "이전 정리본으로" 버튼으로 되돌릴 수 있었습니다.
- **질문하기**: 고른 부분에 대해 물으면 답을 아래에 보여 주고 글은 바꾸지 않았습니다.
- **🎤 말로 고치기**: 지시를 최대 20초 말하면 Whisper로 전사해 바로 고치기에 넣었습니다.
- 서버 모드 `edit`, `ask`: 한 번 쓰고 버리는 Claude 클라이언트를 썼습니다(맥락이 쌓이지 않게). 응답을 빠르게 하려고 **예비 클라이언트를 미리 연결**해 두고, 쓰면 바로 다음 예비를 띄웠습니다.
- 프롬프트(원본 그대로):
  - edit: "당신은 글의 일부를 지시대로 고쳐 쓰는 편집자다. `<selection>`은 고칠 부분, `<instruction>`은 사용자의 지시, `<before>`·`<after>`는 앞뒤 문맥(참고용, 출력하지 않음)이다. 지시대로 고친 `<selection>`의 새 내용만 출력한다. 앞뒤 문맥과 자연스럽게 이어지게 하고, Markdown 형식을 유지한다. 지시가 요구하지 않는 한 사실·숫자·이름을 바꾸거나 새 내용을 지어내지 않는다. `<guide>`의 용어 표기를 따른다. 설명·따옴표·코드블록 없이 결과 본문만 출력한다."
  - ask: "당신은 사용자가 고른 글에 대해 답하는 도우미다. `<selection>`은 사용자가 고른 글, `<instruction>`은 질문이나 요청이다. 글 자체는 바꾸지 않는다. `<selection>`의 내용을 근거로 한국어로 짧고 정확하게 답한다. 글에 없는 일반 지식을 쓰면 그렇다고 밝힌다."
  - 요청 본문: `<before>`(앞 2,000자) `<selection>` `<after>`(뒤 2,000자) `<instruction>`(1~1,000자).

**붙일 곳**
- `server/organizer.py`: 지금은 `append`만 있습니다. `mode`를 받아 `edit`/`ask`면 단발 클라이언트로 처리하는 분기를 추가합니다. `ClaudeAgentOptions(system_prompt=…)`가 모드마다 다르니 클라이언트도 모드별로 만듭니다.
- `web/`: 선택 감지(텍스트 영역의 `selectionStart/End`, 또는 3번의 `data-s/e`), 지시 입력칸, 고치기·질문 버튼.

**주의**
- 고치는 동안 다른 정리(라이브 append)가 같은 칸에 쓰지 않도록 쓰기 작업을 하나씩만 하게(직렬화) 하세요. 원본은 `orgExclusive()`로 묶었습니다.

## 5. 여러 정리 양식과 정리 방식

**원본 동작**
- 정리 양식(설정에 저장):
  - **구조화된 글(기본)**: 원본 기본 규칙 — "한국어 발화는 한국어 문어체 '~다' 체", "Markdown으로 구조화한다: 주제가 바뀌면 '## 소제목', 나열은 목록, 핵심 용어는 필요할 때만 굵게."
  - **회의록**: "안건(주제)별 소제목으로 논의 내용을 정리하고, 결정된 사항은 '**결정:**', 해야 할 일은 '**할 일:**'(담당자·기한이 언급됐을 때만 함께) 줄로 표시한다. 전체를 정리할 때는 끝에 '## 결정 사항', '## 할 일', '## 미결 사항'을 모은다(해당 내용이 있을 때만)."
  - **강의 노트**: "개념은 정의와 함께 굵게 표시하고, 설명·예시·주의점을 목록으로 구분한다. 전체를 정리할 때는 끝에 '## 핵심 정리'를 목록으로 붙인다(새 내용 없이 본문에서만)."
  - **개조식 보고**: "한국 공문 개조식. '□ 대주제', 'ㅇ 세부 내용', '- 부연 설명' 부호와 들여쓰기를 쓰고, 문장은 명사형·음슴체(~함, ~임, ~ 예정)로 짧게 끝낸다. Markdown 소제목 대신 □ 줄을 쓴다."
  - **보도자료체**: "3인칭 서술로 쓰고, 핵심 사실을 단락 앞에 둔다. 발언을 옮길 때는 발언자가 원문에서 확인될 때만 큰따옴표 인용과 함께 밝힌다."
  - **입력용**: 이 저장소의 `SYSTEM_PROMPT`가 바로 이것입니다.
- 양식은 `<guide>` 블록으로 요청 앞에 붙였고, append 세션에는 **지침이 바뀔 때만** 다시 보냈습니다(지금 코드도 같은 방식).
- **정리 방식**: "새 단락 붙이기(append, 빠름·기본)" 또는 "매번 전체 다시 쓰기(full, 쉴 때마다 원문 전체를 다시 정리, 길어질수록 느림)".
- **녹음 중지 후 전체 다듬기**: append로 녹음한 뒤 마지막에 full로 한 번 다시 써서 `# 제목`과 소제목을 갖춘 글로 만들었습니다. full 프롬프트: "당신은 강연·회의 전사문을 완성된 글로 옮기는 편집자다. `<raw>`로 음성 인식 원문 전체가 온다. 처음부터 끝까지 하나의 구조화된 글로 다시 정리한다. 맨 앞에 '# 제목' 한 줄을 붙이고, 흐름에 맞게 소제목으로 나눈다." (+ 공통 규칙)
- **문체 예시**: 평소 쓰는 글(최대 3,000자)을 붙여 두면 어미·문장 길이·구성 습관을 따르게 했습니다("예시의 내용은 가져오지 않는다").
- "전체 다시 정리" 버튼, "이전 정리본으로"(한 단계 되돌리기).

**붙일 곳**
- `server/organizer.py`: `build_guide()`에 양식별 문장을 추가하고, `SYSTEM_PROMPT`를 양식에 따라 고르거나 공통 규칙 + `<guide>`로 나눕니다. full 모드는 단발 클라이언트(4번과 같은 방식)로.
- `web/`: 양식·방식 선택, 설정 저장(localStorage 또는 서버 설정 파일).

**주의**
- "앞 앱에 넣기"를 켠 녹음은 입력용(마크다운 없음) 양식으로 고정하는 게 좋습니다. 원본도 그렇게 했고, 이때 전체 다듬기는 건너뛰었습니다.
- full은 원문이 길면(원본 상한 12만 자) 오래 걸립니다. 진행 표시와 시간 제한을 두세요.

## 6. 시스템 소리 전사 (회의·영상 소리)

**원본 동작** — 입력 소스를 고를 수 있었습니다.
- **앱이 직접 캡처 (권장, macOS 14.2+)**: Swift 앱이 **Core Audio 프로세스 탭**(`AudioHardwareCreateProcessTap` + 집합 장치)으로 Mac 전체 출력 소리를 받아, Float32 PCM을 base64로 페이지에 보내고(`window.mingNative.audio(b64, rate)`), 페이지의 AudioWorklet(`native-feed`)이 이를 재생 그래프에 넣어 마이크와 같은 경로로 처리했습니다. `Info.plist`에 `NSAudioCaptureUsageDescription`이 필요하고, 처음에 "시스템 오디오 녹음" 권한을 묻습니다.
- **마이크 + 시스템 소리**: 두 입력을 GainNode 하나로 섞음(이어폰 권장 — 스피커 소리가 마이크로 다시 들어감).
- **BlackHole 경유**: 가상 오디오 장치(BlackHole 2ch)와 "다중 출력 장치"를 만들어 시스템 출력을 입력 장치처럼 받는 방식. 앱 없이 브라우저로도 됨.
- **Chrome 탭 소리**: `getDisplayMedia({video: true, audio: …, systemAudio: 'include'})`로 탭 소리만 받기(WKWebView에서는 안 됨).
- 시스템 소리는 배경음이 늘 있어 "조용함" 판정이 어렵습니다. 원본은 **적응형 쉼 감지**를 썼습니다: 에너지를 약 30ms로 평활화하고, 배경 수준(floor)을 따라가며(작아지면 즉시, 커지면 아주 천천히) `평활값 < max(0.0001, floor × 4)`를 조용함으로 봤습니다. 또 목소리가 한 번도 없었던 구간은 Whisper에 보내지 않았습니다.

**붙일 곳**
- Swift: 원본의 `SystemAudio.swift`(약 120줄)에 해당하는 캡처 클래스, 페이지와의 메시지(`audio` start/stop, 시작된 샘플레이트 전달).
- `web/app.js`: 입력 소스 선택, `native-feed` 워클릿, 적응형 쉼 감지.

**주의**
- 시스템 오디오 녹음 권한은 서명이 바뀔 때마다(다시 빌드) 다시 물을 수 있습니다.
- 다른 사람의 목소리를 녹음·전사하는 것이므로 참석자 동의 등 법적·윤리적 책임은 사용자에게 있습니다.

## 7. 용어 사전 고급 기능

**원본 동작**
- **CSV 가져오기/내보내기**: 한 줄에 `용어,설명`. 첫 줄이 `용어`/`term` 머리글이면 건너뜀. 내보내기는 Excel이 한글을 읽도록 BOM(`﻿`)을 붙였습니다.
- **자동 학습**: 사용자가 원문이나 정리된 글에서 단어 철자를 고치면 그 단어를 사전에 "자동 추가"로 넣고, 알림의 "취소"로 되돌릴 수 있었습니다.
  잘못 배우지 않게 걸렀습니다: 고치기 전후 어절 수가 같을 때만, 바뀐 어절이 1~2개일 때만, 편집 거리(levenshtein)가 너무 크지 않을 때만, 어미·조사만 바뀐 경우(예: '했다'→'했습니다')는 제외.
- 수동/자동 출처 표시와 필터, 검색, 수정.

**붙일 곳**: `server/dictionary.py`(가져오기·내보내기·출처 필드), `web/`의 사전 화면과 편집 감지.

## 8. 그 밖의 편의 기능

- **시작/중지 효과음**(Web Audio 짧은 비프, 기본 꺼짐).
- **Whisper 상주 서버를 못 쓸 때 whisper-cli로 대신 처리**(느리지만 동작).
- **로그인 시 자동 실행**(`SMAppService.mainApp.register()`), 창을 닫은 상태에서 녹음이 끝나면 알림.
- 메뉴 막대에서 상태(녹음 시간, "정리 중") 표시 — 최소판에도 기본 형태는 있습니다.
- 디버그용: 앱을 `MINGLIVE_DEBUG=1`로 띄웠을 때만 분산 알림으로 페이지 JS를 실행하는 브리지(자동 테스트용).
- 녹음 중 종료하려 하면 확인 창("처리 중인 구간이 사라질 수 있습니다").
